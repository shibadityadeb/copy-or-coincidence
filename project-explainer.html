1 · Problem statement

What are we actually trying to find out?

In one sentence: when several AI agents work together and end up wrong in the same way, how much of that would have happened anyway (because they each would have made that mistake alone), and how much is caused by them talking to each other?

Think of two students in an exam who both write the same wrong answer on question 17. There are three very different stories:

Story 1

Q17 was just hard

Most students got it wrong. Both failing it tells you nothing about them.

Story 2

Same blind spot

Q17 had a tempting trap answer and both fell for it on their own. They think alike, but nobody copied.

Story 3

One copied the other

Student B would have been right, but looked at A's paper and switched. This is the damage caused by interaction.

Many papers see "both wrong" and jump to Story 3. The project's whole job is to measure how much is left over after Stories 1 and 2 are accounted for. That leftover is called the residual.

2 · The trap everyone falls into

Why "9% vs 5%" can mean nothing

Say agent A is wrong 20% of the time and agent B 25%. The naive math says they should both be wrong together 20% × 25% = 5% of the time. You observe 9%. Proof they influence each other?

No. Hard questions are hard for both of them. If they both fail the same tough questions, they will be "wrong together" far more than 5% even if they never talk. Move the slider to see how much of the gap is explained just by questions varying in difficulty.

0 = every question equally hard. 0.18 = quite ordinary for LLM benchmarks, where many questions are either always right or always wrong.

This is the key idea from Eckhardt & Lee (1985), originally about software built by independent teams. The fix: compare against what each agent does on each specific question, not its overall average.

3 · Vocabulary

Words you'll see all the time

agent
One model + its prompt + its settings + its role. Two agents can be the same model with different prompts.
item
One test question.
lure
The tempting wrong answer a question is designed to have (like the intuitive but wrong answer in a trick question).
answer profile
Ask an agent the same question 20 times alone. The spread of its answers (e.g. 60% "12", 30% "10", 10% other) is its profile for that question.
null model
The "nothing interesting is happening" prediction. We compute what should happen if agents do not affect each other, then compare to reality.
residual (Δ)
Observed minus expected. The part the null model cannot explain. This is the finding.
permutation test
Shuffle which of B's answers is paired with which of A's (within the same question) many times. If the real result looks like the shuffled ones, there's no real link.
helpful / harmful flip
B changes from wrong to right after seeing A (helpful), or from right to wrong (harmful). If both happen about equally, B is just copying, not thinking.
contested item
A question where the agents don't have one strongly preferred answer. Interesting things only happen here.
4 · The refined research question

It splits into two questions

Q1 · Similarity

Do the agents think alike?

Working completely alone, how similar are their answer profiles? Does it depend on whether they come from the same model family, and on what kind of mistake it is?

Stories 1 and 2. No talking involved.

Q2 · Dependence

Does talking make them converge?

When agents see each other's answers, do they agree more than their solo profiles predict? Towards the truth or towards the lure? And why: copying, a chain reaction, or failing to spot the error?

Story 3. The main contribution.

Why an error survives also has three different causes, and they need different fixes:

Couldn't see it

The checker shares the same blind spot, so the mistake looks fine.

Fix: use a more different checker.

Was talked out of it

The checker was right, then gave in to the peer (conformity).

Fix: protect independent opinions.

Saw it, couldn't fix it

Knew something was off but couldn't repair it.

Fix: point to the exact faulty step.

5 · The process

The whole pipeline as a flowchart

Each box is a step. Green dashed boxes are gates: if the check fails, stop and fix before moving on.

1

Build the test set ("Correlated Error Probe")

~600 fresh, auto-generated questions so the models haven't seen them before. Four kinds: trick questions with lures, logic puzzles, math with distractors or missing info, and constraint puzzles. Each question stores its correct answer, its lure, and why it's designed to cause errors.

output → datasets/cep_v1
2

Build automatic answer checkers

Code (not an AI judge) decides if an answer is right, which error type it is, and whether it hit the lure. An AI judge would share the agents' blind spots and fake the very effect we're measuring.

output → checkers + tests
✓

Gate: are the checkers trustworthy?

Compare against 150 answers you label by hand. Need ≥95% agreement on right/wrong and ≥85% on error type. Then freeze the checker.

3

Layer 0: every agent answers alone, 20 times per question

No communication. This gives each agent's answer profile for every question. Everything else is compared against this.

output → per-question answer profiles
✓

Gate: Experiment 1, the "should be zero" test

Pair two agents that definitely don't communicate. The residual must come out ≈ 0. If it doesn't, the pipeline has a bug. (The naive method would wrongly show "excess" here, which proves the point.)

4

Let them interact (the core experiment)

A answers, B sees A's answer and then answers. Also the reverse order (B→A), and a control where B sees a random answer. Each run repeated 5 times per question.

output → paired answers, logged row by row
5

Compare observed vs expected

Expected = how often they'd match if B just answered from its own solo profile. Observed = how often they actually matched after interacting. Difference = residual. Permutation test says if it's real.

6

Break the residual down

Which direction?

Did they converge on the truth or on the lure?

Copying or thinking?

Helpful vs harmful flips; does a random answer move B just as much?

Does order matter?

If A→B differs from B→A, whoever speaks first wins: a cascade.

7

Statistics and write-up

Confidence intervals by resampling questions, a mixed model that accounts for question difficulty, pre-registered hypotheses. Then: "here's how much of the joint error is explained by the agents' own behaviour, here's how much isn't, and here's why."

8 · Reading the results

If you see this, it means that

You observeMeaning
Non-talking agents wrong together more than naive math saysNormal. Just difficulty. Our residual should be ≈ 0 here.
Big match residual, but not toward the lureB copies whatever A said. Copying, not a shared blind spot.
Big residual toward the lureInteraction pushes both towards the tempting wrong answer.
A→B gives different results from B→AWhoever goes first wins: a cascade.
B flips regardless of whether A's argument is validB follows conclusions, not reasoning.
Helpful flips ≈ harmful flipsB isn't evaluating, it's copying.

Other things that can fake a positive result: B copying A's formatting so answers look identical, A's message restating the question more clearly, or simply a longer prompt. The controls above rule these out.

9 · Conclusions

What the minimum project can and can't tell us

MVP setup: Qwen3.5-4B as both agents, 300 questions (100 trick, 100 logic, 100 math), 20 solo samples each, protocols: alone, A→B, B→A, random-answer control, 5 runs each. About 12M tokens, two Kaggle sessions.

It CAN conclude

  • Whether seeing a peer's answer creates agreement beyond what each agent does alone
  • How much of that is blind copying
  • Whether the convergence heads toward the lure
  • Whether it differs by error type

It CAN'T conclude

  • Anything about model family / lineage
  • Whether failures are about detecting vs repairing
  • Whether longer chains cause cascades

These come in the expansion stages.

Counts as a contribution

  • A validated method that gives zero for non-talking agents and a replicated residual under interaction
  • How much "debate failure" was predictable from solo behaviour
  • A mechanism that passed a pre-registered test
  • Released question generator, code and logs anyone can rerun

Does NOT count (already known)

  • "Multi-agent systems fail"
  • "Models make correlated errors"
  • "Diversity improves accuracy"
  • "Debate ≈ voting"
  • Accuracy tables without the null model

The honest framing, whatever the data show: we measured how much of the agents' joint error is explained by each agent's own behaviour and how much isn't; here's the split, here's what explains the rest, and here's what didn't.

10 · Timeline

Six months, each with a pass/fail gate

Build order inside the MVP: question generator + checkers → model runner with logging → Exp 0 → Layer 0 → null-model code + Exp 1 (must be zero) → sequential protocol + Exp 7 with random-answer control → analysis. Only then add a second model.

1Understand

Read the core papers, get Qwen3.5-4B running locally, re-derive the toy examples by hand, write a 2-page note.

Gate: you can explain on a whiteboard why difficulty alone creates "excess" joint error.
2Build

Question generator (3 families), checkers + tests vs 150 hand labels, data schema, runner, null-model code tested on fake data with known copying. Exp 0.

Gate: checker hits 95% / 85%; re-runs are identical; code recovers the known copying rate.
3Baseline

Layer 0 on Kaggle, Exp 1, compare naive vs per-question expectation on real data, power analysis, pre-register Exp 7.

Gate: Exp 1 residual is indistinguishable from zero on every question family.
4Controlled

Exp 7 (both orders, steps shown/hidden) + random-answer control; Exp 4 for one model pair; full analysis.

Gate: hypotheses tested exactly as pre-registered; alternative explanations checked.
5Mechanism

Pick the control conditions month 4 points to; try one intervention that should shrink the residual.

Gate: one pre-registered mechanism prediction that held (and could have failed).
6Write

Replicate on a second model family, robustness checks, write the paper, release everything. Workshop first.

Gate: main result reproduces in direction and rough size.

If a gate fails, repeat the month. That's the plan working, not failing.

11 · Don't fool yourself

Pitfalls to check before believing any result

  • Did you compare against per-question expectations, and did Exp 1 give ≈ 0?
  • Are you calling "they think alike" (Q1) "they influence each other" (Q2)?
  • Is any label produced by an AI judge? Not allowed for the main numbers.
  • Could A and B be leaking info through seeds, cache or batching?
  • Are settings (temperature, quantisation, model version) identical across conditions?
  • Did you compare bigger vs smaller models only at matched accuracy?
  • Did you treat each run as independent? The real unit is the question.
  • "Communication fixed errors" — or did B just copy a more accurate A? Check helpful vs harmful flips.
  • Write two alternative explanations before your own interpretation.
12 · Practical setup

Models, compute, sample size

Models

Workhorse: Qwen3.5 (0.8B–27B). Different families later: Gemma 4, Phi-4-mini, Ministral, Llama 3, SmolLM3, OLMo 3, Granite.

Compute

Develop on the Mac with 20 questions. Real runs on Kaggle 2×T4 with vLLM: ~3–5 hours per big run.

How many questions?

400 questions × 5 runs catches a 5-point residual 90% of the time. Under 200 questions, ignore residuals below 10 points.

Settings: temperature 0.7, structured JSON output (steps, final, confidence), every row logged to append-only JSONL with seed, model version and checker version.
